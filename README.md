# Lina’s Homeworks

Сайт для публикации, отправки и ручной проверки домашних работ. Node.js 24+, SQLite и обычный HTML/CSS/JavaScript. Установка npm-пакетов не нужна.

## Структура проекта

| Путь | Что внутри |
| --- | --- |
| `src/server/` | HTTP API, правила валидации домашних работ и контракт JSON |
| `src/server/storage/` | Инициализация SQLite и схема таблиц |
| `src/web/` | Публичные страницы, кабинет ученика, админка и общие стили |
| `test/` | Интеграционные тесты и проверки формата заданий |
| `legacy/` | Исходный HTML-прототип для сравнения |
| `Dockerfile` и `compose.yaml` | Сборка и запуск приложения с постоянным томом |

## Запуск в Docker

Из папки с `compose.yaml` выполни:

```sh
cp .env.example .env
```

Впиши в `.env` свой пароль преподавателя длиной от 12 символов. Для просмотра на своём компьютере оставь `COOKIE_SECURE=0`.

```sh
docker compose up -d --build
```

Открой http://localhost:8080. Вход преподавателя находится по адресу http://localhost:8080/admin.

Для публичного запуска поставь перед приложением HTTPS-прокси, направленный на `127.0.0.1:8080`, и установи `COOKIE_SECURE=1`. У прокси должны сохраняться заголовок Host и возможность загрузки файлов до 20 МиБ. Если прокси перезаписывает `X-Forwarded-For` адресом клиента, установи `TRUST_PROXY=1`, чтобы лимит входа применялся отдельно к каждому адресу. Не включай эту настройку, если прокси сохраняет присланный клиентом `X-Forwarded-For`: тогда заголовок можно подделать. Используй один экземпляр приложения. SQLite и загруженные файлы сохраняются в томе `homework_data`. Команда `docker compose down -v` удаляет данные.

### Резервное копирование и восстановление

Создай согласованную копию SQLite и медиа одной командой:

```sh
./scripts/backup.sh
```

Скрипт на время копирования останавливает работающий сайт, собирает весь том в `backups/homework-<UTC-время>.tar.gz`, проверяет архив и снова запускает сайт, если он работал до копирования. Архив создаётся с правами владельца и читается только текущим пользователем. Он не зашифрован и содержит имена, ответы, оценки и загруженное аудио: храни его в защищённом месте и шифруй перед передачей или отправкой в облако. Каталог `backups/` исключён из Git; регулярно переноси копии на отдельный защищённый носитель или сервер. Чтобы выбрать другой каталог, задай `BACKUP_DIR=/путь/к/копиям`.

Для восстановления укажи конкретный архив:

```sh
./scripts/restore.sh --confirm-replace /путь/к/homework-20261123T120000Z-12345.tar.gz
```

Перед заменой скрипт создаёт копию текущего тома, проверяет архив и целостность SQLite, затем заменяет данные и восстанавливает прежнее состояние сервиса. Флаг `--confirm-replace` обязателен, потому что восстановление заменяет текущие работы, сдачи и медиа. Сначала проверь восстановление на отдельном тестовом экземпляре; не распаковывай архив вручную поверх работающего сайта.

## Работа с заданиями

В админке создай черновик вручную или вставь JSON. Там же можно скачать шаблон и JSON Schema. Размер готового задания ограничен 4 МиБ; файл для импорта может быть до 8 МиБ. Список работ поддерживает поиск по названию и коду и фильтр по статусу; сдачи можно найти по имени ученика и отфильтровать по наличию оценки. В просмотре сдач можно скачать CSV со всеми ответами, оценками и формулировками вопросов — независимо от текущего поиска и фильтра. Для внешней LLM используй схему как формат ответа, вставь результат в редактор и проверь содержимое перед публикацией. Поля, неприменимые к типу вопроса, заполняются пустыми строками или массивами. У типов choice и multi должно быть не меньше двух вариантов. Для match нужны минимум две пары «текст ↔ картинка», для flash — минимум одна карточка. `solution` используется только для английского слова или фразы в виселице. Оценку и обратную связь публикует преподаватель; по ключу ответов сайт может предложить баллы для choice, multi и text, которые преподаватель проверяет и подтверждает.

После публикации отправь ученику ссылку на работу или её код. Для работы можно указать необязательный срок сдачи. Ученик увидит его до отправки; поздние ответы принимаются и отмечаются в учительской и на личной странице результата. Ученик вводит только имя. После отправки ученик должен сохранить личную ссылку на результат. Любой, у кого есть эта ссылка, сможет открыть соответствующую оценку и комментарий. Изменение задания не меняет уже сданные работы. Архивирование закрывает новые отправки, сохраняя ответы и результаты.

Медиа можно загрузить в редакторе либо указать прямой HTTPS-адрес. Загруженные файлы открываются по своим адресам, поэтому не размещай там личные документы. Данные старого HTML хранились в браузере и не перенесены в SQLite автоматически.

Чтобы посмотреть объём загруженных файлов и найти те, на которые сохранённые задания и сдачи не ссылаются, выполни `./scripts/media-report.sh`. Отчёт ничего не удаляет: файл может использоваться в несохранённом черновике преподавателя.

## Разработка

```sh
ADMIN_PASSWORD='replace-for-local-use' COOKIE_SECURE=0 npm start
npm test
```

Тесты поднимают сервер с отдельной временной SQLite и проверяют типы упражнений, авторизацию, публикацию, отправку, ручную оценку, архивирование, медиа, дедлайны, CSV, поиск и пагинацию. Отдельно проверяется миграция существующей базы без новых полей дедлайна.
